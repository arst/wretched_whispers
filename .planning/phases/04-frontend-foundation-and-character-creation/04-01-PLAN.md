Add CORS configuration to the API's Program.cs to allow the Next.js dev server (http://localhost:3000) to communicate cross-origin. This is a blocking prerequisite — without it, the frontend cannot reach any API endpoint.

1. After `var builder = WebApplication.CreateBuilder(args);`, add:
```csharp
builder.Services.AddCors(options =>
{
    options.AddDefaultPolicy(policy =>
    {
        policy.WithOrigins("http://localhost:3000")
              .AllowAnyHeader()
              .AllowAnyMethod();
    });
});
```

2. After `app.UseAuthorization();`, add:
```csharp
app.UseCors();
```

The order matters: UseAuthentication -> UseAuthorization -> UseCors must be the middleware sequence. Do NOT add AllowCredentials (the API uses Bearer tokens in Authorization header, not cookies).

Verify the existing solution still builds and all tests pass after this change.

**2. Zustand auth store with localStorage persistence (src/stores/authStore.ts)**

Follow the pattern from RESEARCH.md. Use `persist` middleware with `skipHydration: true` to avoid hydration mismatches (Pitfall 4 from research). The store must expose: `accessToken`, `refreshToken`, `expiresAt`, `isAuthenticated`, `isHydrated`, `setTokens()`, `logout()`.

Key implementation details:
- Use `skipHydration: true` in persist config
- Add `isHydrated` boolean (starts false, set true after rehydrate)
- Export both the store hook (`useAuthStore`) and a non-hook accessor for use in lib/api.ts
- Storage key: `'ww-auth'`

**3. Authenticated API client (src/lib/api.ts)**

Create a centralized fetch wrapper that:
- Reads accessToken from `useAuthStore.getState()` (non-hook access)
- Attaches `Authorization: Bearer <token>` header to all requests
- Handles 401 responses by attempting token refresh via POST /auth/refresh
- On successful refresh: updates store via `setTokens()`, retries original request
- On failed refresh: calls `logout()`, does NOT retry
- Base URL from `process.env.NEXT_PUBLIC_API_URL`
- Exports `apiFetch(path: string, options?: RequestInit): Promise<Response>`

Follow the exact pattern from RESEARCH.md Pattern 1. Do NOT use `?useCookies=false` in the API client — that parameter is only needed on the login endpoint specifically.

**4. Auth helper functions (src/lib/auth.ts)**

Create helper functions wrapping the auth API calls:
- `login(email: string, password: string): Promise<LoginResponse>` — calls POST /auth/login?useCookies=false, updates auth store on success
- `register(email: string, password: string): Promise<void>` — calls POST /auth/register
- `verifyToken(): Promise<boolean>` — calls GET /auth/me, returns true if 200
- `logout(): void` — clears auth store

These helpers are used by the auth screens in Plan 02.
