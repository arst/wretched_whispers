- Response: text/event-stream with events: narrative, tool_result, state_update, done, error
- narrative: { text: string } -- word or few words of narrator text
- tool_result: { function: string, result: any } -- dice rolls, stat assignments

- done: {} -- stream complete
- error: { message: string } -- error occurred

**1. Session store (src/stores/sessionStore.ts)**

Zustand store managing the current game session state. This is the backbone of the chat UI.

State shape:
```typescript
interface Message {
  id: string;           // Generated UUID for React keys
  role: 'user' | 'assistant' | 'system';
  content: string;
  authorName: string | null;
  toolResults: ToolResultEvent[];  // Attached to the GM message they belong to
}

interface SessionState {
  sessionId: string | null;
  status: string | null;
  messages: Message[];
  isStreaming: boolean;
  streamingMessageId: string | null;  // ID of the message currently being streamed
  streamingText: string;              // Text accumulating during streaming
  error: string | null;

  // Actions
  setSession: (sessionId: string, status: string, messages: ChatMessageDto[]) => void;
  addPlayerMessage: (content: string) => void;
  startStreaming: () => void;         // Creates a new empty assistant message, sets isStreaming=true
  appendNarrativeChunk: (text: string) => void;  // Appends to streamingText
  addToolResult: (result: ToolResultEvent) => void;  // Attaches to current streaming message
  setStateUpdate: (update: StateUpdateEvent) => void;
  finishStreaming: () => void;        // Copies streamingText to message.content, sets isStreaming=false
  setError: (message: string) => void;
  clearError: () => void;
  reset: () => void;
}
```

Critical implementation detail for Pitfall 5 (excessive re-renders during streaming):
- Use a separate `streamingText: string` field that `appendNarrativeChunk` updates. The `ChatWindow` message list does NOT re-render on `streamingText` changes -- only the dedicated streaming message component reads it via a focused Zustand selector. When streaming finishes, `finishStreaming` copies `streamingText` into the message's `content` and clears `streamingText`.

Implementation:
- Use `@microsoft/fetch-event-source` with `fetchEventSource()`
- POST to `${NEXT_PUBLIC_API_URL}/sessions/${sessionId}/actions`
- Headers: `Authorization: Bearer ${accessToken}`, `Content-Type: application/json`
- Body: `JSON.stringify({ message })`
- Before sending: call `sessionStore.addPlayerMessage(message)` and `sessionStore.startStreaming()`
- Event handlers:
  - `narrative`: call `sessionStore.appendNarrativeChunk(parsed.text)`
  - `tool_result`: call `sessionStore.addToolResult(parsed)`
  - `state_update`: call `sessionStore.setStateUpdate(parsed)`
  - `done`: call `sessionStore.finishStreaming()`, then `ctrl.abort()` to stop the connection (Pitfall 3)
  - `error`: call `sessionStore.setError(parsed.message)`, call `sessionStore.finishStreaming()`
- `onerror`: call `sessionStore.finishStreaming()`, throw to stop retries
- AbortController ref: abort any in-flight stream before starting a new one
- Cleanup on unmount: abort in-flight stream
- Handle 409 Conflict: if the fetch itself returns 409 before SSE starts, set error "GM is already responding" and do NOT start streaming state

**Game session page (src/app/sessions/[id]/page.tsx)**

`"use client"` page that is the heart of the game experience.

**On mount:**
1. Extract `id` from route params
2. Call `apiFetch(`/sessions/${id}`)` to load the SessionDetailDto
3. Populate session store via `setSession(id, status, messages)`
4. If session has no messages and status is "character-creation": show the SplashScreen
5. If session has existing messages: show the ChatWindow immediately with loaded messages
6. If session status is "character-creation" and there are no messages: automatically send an initial action to trigger the GM's opening message. The message can be empty string or a brief prompt like "begin" -- the backend's GM agent handles the character creation conversation. Call `sendAction("begin")` to kick off the narrator.
7. When the first narrative SSE event arrives during the splash screen: transition from splash to chat view

**Character creation flow:**
- Character creation is simply the chat interface in a session with status "character-creation"
- The narrator (backend GM agent) drives the conversation: asking for the player's name, rolling stats, assigning equipment
- The player responds via the same ChatInput used for gameplay
- tool_result events (dice rolls, stat reveals) appear as ToolResultCallouts within the conversation
- state_update events may change the session status from "character-creation" to "in-progress" when creation completes
- No special frontend logic needed -- the chat interface IS the character creation interface

**Page layout:**
- Full height layout: flex flex-col h-screen (or min-h-screen)
- Header at top (already rendered by sessions layout)
- ChatWindow fills the middle (flex-1 overflow-y-auto)
- ChatInput fixed at bottom
- When splash is showing: SplashScreen replaces the chat area
- Session name in the header (pass to Header or show as a sub-header)

**Error handling:**
- If session load fails with 404: show "Session not found" error page, link back to /sessions
- If SSE stream errors: show error toast/banner in doom-pink above the ChatInput, auto-dismiss after 5 seconds
- If 409 Conflict: show "The narrator is still speaking..." message, don't disrupt existing stream

**Streaming UX flow (from user's perspective):**
1. User types message, presses Enter
2. Player message appears immediately in the chat
3. ThinkingIndicator appears (GM is thinking...)
4. First narrative chunk arrives -- ThinkingIndicator replaced by streaming NarratorMessage
5. More narrative chunks stream in, text grows word-by-word (typewriter effect)
6. tool_result events arrive -- ToolResultCallouts appear after the narrative text
7. done event -- streaming finishes, message is finalized
8. Input re-enables, user can respond

**Cleanup:**
- On unmount: abort any in-flight SSE stream (handled by useSseStream hook cleanup)
- Reset session store on unmount or when navigating away
