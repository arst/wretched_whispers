```
Response: { messages: ChatMessageDto[], totalMessages: number, page: number, pageSize: number }
```

Note on pagination direction: Backend returns messages in chronological order (oldest first).
Page 1 = oldest messages. The initial session load via GetSessionDetail uses page=1&pageSize=50
which gets the FIRST 50 messages. For a session with 120 messages, the frontend currently has
messages 1-50, NOT the latest 50.

Actually, reviewing the code more carefully: GetSessionDetail loads ALL chat history into memory,
then paginates with Skip/Take starting from offset 0. So page=1 returns the OLDEST messages.
The frontend displays them in order. For load-more, we need the NEXT page (page 2, 3, etc.)
of OLDER messages that were not loaded initially... but wait, the initial load gets page 1
(the oldest). This means newer messages are on HIGHER page numbers.

**Revised pagination strategy:** Since the initial load gets page 1 (oldest 50 messages out of N),
and the frontend needs the LATEST messages first (user sees the end of conversation), this is a
problem. Two options:
1. Change initial load to get the LAST page, then load-more goes backwards
2. Load all messages initially (current behavior with large pageSize), add load-more for truly long sessions

The simplest correct approach: On initial session load, request the LAST page of messages.
Calculate: `lastPage = Math.ceil(totalMessages / pageSize)`. Then for load-more, request
`lastPage - 1`, `lastPage - 2`, etc.

However, modifying the initial load page calculation is in page.tsx which Plan 01 already modifies.
The executor should: in the loadSession function in page.tsx, after getting the session detail,
if the page received is 1 and totalMessages > pageSize, make a follow-up call to get the last page.

**Simpler approach chosen:** Keep the backend behavior as-is. In the initial session load (page.tsx),
calculate the last page and request it. For load-more, decrement page numbers. This way:
- Initial load: `GET /sessions/{id}?page={lastPage}&pageSize=50` (most recent messages)
- Load more: `GET /sessions/{id}/messages?page={lastPage-1}&pageSize=20` (older messages)

Wait -- GetSessionDetail takes page/pageSize as query params. So the initial load CAN request
the last page. Update page.tsx accordingly.
