<specifics>
## Specific Ideas

### Critical Bugs (must fix)
1. **ScrollRestrictionPolicy.CanUseScrolls is inverted in Character.Cast** — When `CanUseScrolls` returns true (character CAN cast), the code blocks them. Fix the condition.
2. **Encounter.IsStarted / IsEnded have public setters** — Change to `private set` to match every other entity.

### High Severity Findings (from audit)
3. **Character is a 458-line god class** — Attack, Defend, Challenge, Cast, BuyItem, Rest, broken-state resolution all in one class
4. **9 boolean injury flags** — IsInfected, IsDead, HasLostEye, HasStabbedLung, HasBrokenHand, HasCrushedFoot, HasSeveredArm, HasSmashedFace, IsDizzyFromMagic
5. **Inventory is a record with mutable List<T>** — mixing value and reference semantics
6. **CharacterPlugin bypasses Character aggregate** — directly calls character.Inventory.AddItem()
7. **Abilities is mutable pretending to be a value object** — ModifyAbility mutates in place

### Medium Severity Findings (optional scope)
8. Adversary is nearly anemic (only ReceiveDamage and Retreat)
9. Omens mechanic unimplemented (TrySpend/Refill never called)
10. Misery.Psalm always empty
11. DawnResult defined but unused
12. Negative DamageDealt in DefenceOutcome
13. Unbounded recursion in Defend on critical rolls

### Low Severity (include sealing, defer rest)
14. Seal Campaign, Adversary, and inconsistent BrokenOutcome subtypes
15. Typo "Calender" in Campaign.cs (fix opportunistically)

</specifics>

<code_context>
## Existing Code Insights

### Reusable Assets
- `BrokenOutcome` hierarchy: discriminated union pattern with factory methods — could inform injury representation design
- `ArmorTier` hierarchy: strategy/type-object pattern with singleton instances — armor reduction logic should move here
- `readonly record struct` pattern: used for HitPoints, AbilityScore, Damage, DiceExpr, AttackProfile — established immutable value object pattern
- `TestBase` class: provides `protected Dice Dice` property for all tests — test infrastructure is ready

### Established Patterns
- Static factory methods (`Character.Create()`, `Weapon.Create()`, etc.) — use for any new types
- Private `[JsonConstructor]` — separates deserialization from domain creation
- Sealed domain entities — convention to follow (Campaign and Adversary are exceptions to fix)
- Primary constructors for services — use for any new services
- Domain services for cross-aggregate coordination — `CampaignService`, `EncounterService` already exist

### Integration Points
- `CharacterPlugin` (Semantic layer): directly manipulates Character — must update after aggregate boundary fixes
- `CampaignPlugin` (Semantic layer): has duplicate orchestration paths — may need cleanup
- `EncounterPlugin` (Semantic layer): calls EncounterService — already follows the pattern
- EF Core persistence: uses JSON blob pattern — injury representation change must serialize/deserialize correctly
- Existing tests: ~comprehensive coverage — run to catch regressions from refactoring

</code_context>
