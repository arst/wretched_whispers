       Primary constructor: `GameSessionService(IServiceProvider serviceProvider, IConfiguration configuration, ICampaignsRepository campaignsRepository, IChatHistoryRepository chatHistoryRepository, ICharactersRepository charactersRepository, WretchedWhispersDbContext dbContext, ResiliencePipelineProvider<string> resilienceProvider)`

       Suppress SK experimental warnings: `#pragma warning disable SKEXP0001` and `#pragma warning disable SKEXP0110`

       **Core method: `async IAsyncEnumerable<SseEvent> ProcessAction(Guid sessionId, string playerMessage, [EnumeratorCancellation] CancellationToken ct)`**

       Implementation flow:
       a. Load campaign by sessionId: `await campaignsRepository.Get(sessionId)`. If null, yield error event and yield break.
       b. Get chat sessions for campaign, use the first session ID.
       c. Load existing chat history: `await chatHistoryRepository.LoadSession(chatSessionId, ct)`. If null, create new ChatHistory.
       d. Build Kernel per-turn using `BuildKernelForSession()` (private method).
       e. Create GM agent using `CreateGameMasterAgent(kernel)` (private method).
       f. Begin a database transaction: `await dbContext.Database.BeginTransactionAsync(ct)` -- this is the transactional buffering per locked decision. Individual plugin SaveChanges calls are captured in the transaction.
       g. Add user message to chat history and save: `await chatHistoryRepository.SaveMessage(chatSessionId, new ChatMessageContent(AuthorRole.User, playerMessage), ct)`
       h. Wrap agent invocation in resilience pipeline: `var pipeline = resilienceProvider.GetPipeline("llm-retry")`
       i. Inside the resilience-wrapped call:
          - Create a `ChatHistoryAgentThread` and populate from loaded chat history
          - Use `agent.InvokeStreamingAsync(new ChatMessageContent(AuthorRole.User, playerMessage), thread, cancellationToken: ct)`
          - Accumulate narrative text from `StreamingChatMessageContent` chunks. For each chunk with non-empty Content, yield `new SseEvent("narrative", new { text = chunk.Content })`
       j. After streaming completes, read thread messages via `thread.GetMessagesAsync(ct)` to extract FunctionCallContent and FunctionResultContent. For each FunctionResultContent, yield `new SseEvent("tool_result", new { function = funcResult.FunctionName, result = funcResult.Result })` -- per locked decision, tool calls emit as separate structured SSE events.
       k. Save the full assistant response to chat history.
       l. Commit the database transaction: `await dbContext.Database.CommitTransactionAsync(ct)` -- per locked decision, all state changes committed only after full success.
       m. Build state snapshot from current campaign + character state. yield `new SseEvent("state_update", stateSnapshot)` with fields: campaignId, currentDay, currentHour, characterId, characterHp, characterMaxHp, miseryCount, status.
       n. On ANY exception in the try block: `await dbContext.Database.RollbackTransactionAsync()` -- per locked decision, discard partial response on LLM error, game state not modified. Then yield `new SseEvent("error", new { message = "..." })`.

    2. **Add POST /sessions/{id}/actions to SessionEndpoints.cs**:
       Per locked decisions:
       - POST /sessions/{id}/actions returns SSE stream directly (Content-Type: text/event-stream)
       - Per-turn SSE: client opens connection, receives streamed response, connection closes
       - 409 Conflict if GM response already in progress for same session
       - GM sends first message automatically when new session is created (handle the case where this is the first action in a new session -- if chat history is empty, this is the GM's first turn)

       Implementation:
       ```csharp
       group.MapPost("/{sessionId}/actions", async (
           Guid sessionId,
           PlayerActionRequest request,
           GameSessionService gameService,
           SessionConcurrencyGuard guard,
           HttpContext http,
           CancellationToken ct) =>
       {
           // 409 check BEFORE any response writes (per research Pitfall 6)
           if (!await guard.TryAcquire(sessionId))
               return Results.Conflict(new { error = "GM response already in progress" });

           try
           {
               // Set SSE headers
               http.Response.ContentType = "text/event-stream";
               http.Response.Headers.CacheControl = "no-cache";
               http.Response.Headers.Connection = "keep-alive";

               await foreach (var sseEvent in gameService.ProcessAction(sessionId, request.Message, ct))
               {
                   await http.Response.WriteAsync($"event: {sseEvent.EventType}\n", ct);
                   await http.Response.WriteAsync($"data: {sseEvent.JsonData}\n\n", ct);
                   await http.Response.Body.FlushAsync(ct);  // CRITICAL: flush after each event (Pitfall 2)
               }

               // Signal stream completion
               await http.Response.WriteAsync("event: done\ndata: {}\n\n", ct);
               await http.Response.Body.FlushAsync(ct);
               return Results.Empty;
           }
           catch (OperationCanceledException)
           {
               // Client disconnected -- no error needed, just stop
               return Results.Empty;
           }
           catch (Exception)
           {
               // If response hasn't started, we could return error status.
               // But if it has started, we must use SSE error event.
               // Since we set headers above, response has started -- use SSE error.
               try
               {
                   await http.Response.WriteAsync("event: error\ndata: {\"message\":\"An unexpected error occurred\"}\n\n", ct);
                   await http.Response.Body.FlushAsync(ct);
               }
               catch { /* Response may be closed, swallow */ }
               return Results.Empty;
           }
           finally
           {
               guard.Release(sessionId);
           }
       }).RequireAuthorization();
       ```

       Add necessary usings at top of SessionEndpoints.cs: `WretchedWhispers.Api.Models`, `WretchedWhispers.Api.Services`.
